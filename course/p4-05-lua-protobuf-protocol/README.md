# 4.5　Lua 反推 Protobuf 协议

> 状态：🟢 已完成（正文 + 演示程序 + 字段级验证）｜演示程序：`正课/lesson-4.5.exe`

## 一、本章的目的

很多 Unity+Lua 手游（尤其 SLG）的**网络协议在 Lua 层**：Lua 定义消息、用一个 lua protobuf 库收发。这一课从 Lua 代码把整套 **`.proto`（消息定义）+ opcode 映射（cmd↔消息）** 还原出来，之后就能自己解包 / 造包 / 改包。这是 3.5（C# 层的 FlatBuffers）在 Lua 层的对应——两大序列化库分属两层。

> **protobuf 为什么能反推——名字在 Lua、不在 wire**：protobuf 的 wire 格式**只有 tag 号（字段序号）+ 类型，没有字段名**。所以只抓封包**反推不出字段名**（和 FlatBuffers 生成代码带名字不同，3.5）。字段名从**Lua 侧的消息定义**来——`protoc-gen-lua` 把每个 `.proto` 编译成 `_pb.lua`，里面逐字段显式注册 `name/number/type/label`，名字、tag、类型、标签全在，能**无损反推**。

## 二、操作指南

### 第 1 步 · 认形态（决定反推方式）

Lua 里 protobuf / 序列化**不止一种**，按大致常见度：

| 形态 | 长什么样 | 反推 | 真实例子 |
|---|---|---|---|
| **① lua-protobuf(starwing) + `pb.load`**（现代主流，尤其 LuaJIT） | 内嵌一段 `.pb`（FileDescriptorSet）二进制，`pb.load` 一次注册；Lua 文本**看不到字段名** | dump 那段 `.pb` → `protoc --decode FileDescriptorSet`/python（descriptor 自描述）→ 反推 `.proto` | Farlight/igame（VTwin `com.farlightgames.vtwin.ce`）：protobuf over WebSocket，schema `Pb/w3game.pbe` 二进制 |
| **② protoc-gen-lua 逐字段 `_pb.lua`**（经典 ToLua 内置，**本课 demo**） | 每字段一串 `X.name/number/type/label=…`，名字铺在 Lua 文本里 | 解析注册调用 → 拼 `.proto`（纯文本，零依赖） | ToLua 内置 `Assets/ToLua/Lua/protobuf/`；老一代 cocos/ToLua |
| **③ sproto**（云风，国产 SLG 常见，**不是 protobuf**） | `sprotoparser`/`prototool` 解析 `.sproto`，收发 `.spb` | 按 sproto 自己的 wire 格式解 | `com.bw.ud.googleplay`（`Net/`）、`com.en10.ms.gp`、`com.eb.en.gp2`（`c2s.spb`） |
| **④ FlatBuffers / 自定义**（少数） | FlatBuffer 表当容器 / 私有二进制 | 按 FlatBuffer schema 或私有格式逆 | `com.bandainamcoent.tensuramrkww`（FlatBuffer 装 lua 文本） |

> **认形态时把这几种都过一遍**：现代（尤其 LuaJIT）多是 starwing `pb.load(.pb)`（文本里没字段名，去 dump 那段描述符）；国产 SLG 一批用 **sproto**（另一套 wire 格式，按 sproto 自己的格式解）；逐字段 `_pb.lua` 是其中一种、不是唯一。
>
> ⚠️ **corpus 实况（诚实说明）**：翻了 253 份真实 lua 解密 recipe，**没有一份直接出现游戏自带的逐字段 `_pb.lua`**——recipe 重点是"怎么解密拿到 lua 源码"，很少深挖协议库。能确认的信号：sproto 至少 3 个包、Farlight igame 是 protobuf-over-wire 二进制 schema。recipe 里高频的 `tdr.lua`/`protobuf.lua`/`protoc.lua` **大多是 xLua 自带样板**（存在只是框架带了它，判协议库看游戏实际收发点用哪个）。

### 第 2 步 · 从 Lua 定义反推 `.proto`（形态②）

解析 `_pb.lua` 的注册调用 → 按 message 的 `fields` 列表聚字段 → 每字段 `label type name = number` → 拼成 `.proto`。type/label 按 protobuf 常量映射：`5=int32 9=string 8=bool 11=message 14=enum`；`1=optional 2=required 3=repeated`（查表别猜；`type=11/14` 的具体类型在 `message_type`/`enum_type` 属性里）。

### 第 3 步 · 找 opcode 映射（cmd ↔ 消息）

收发包按**协议号**分发。叫法五花八门（`cmd`/`cmdid`/`msgid`/`msgType`/`protoId`），组织方式常见三种：
```lua
opcode = { [1001] = "LoginReq", [2001] = "BattleResult" }   -- a 显式映射表（最好逆）
net.register(1001, "LoginReq", onLoginRsp)                    -- b 注册时绑 cmd（扫所有 register）
-- c cmd = 消息名 hash / 枚举，散在多个文件
```
有了 `.proto` + 协议号映射，给定封包（cmd + body）→ 按 cmd 找消息 → 用 `.proto` 解 body；反过来也能造包。

### 第 4 步 · 验证

本课有答案 `net.proto`，反推产物和它**逐字段核对完全一致**（消息名 / 字段名 / 类型 / 标签 / tag 全对）。真实场景没答案，就用 **4.4 的动态 hook**：hook `pb.encode`/`pb.decode`（或收发点）抓真实封包，用还原的 `.proto` 解出来，字段对上、round-trip 一致 = 还原正确。

### 第 5 步 · protoc 生成任意语言类，写自己的工具

`.proto` 和 `.fbs` 一样**语言中立**——`protoc --python_out/--go_out/--cpp_out net.proto` 生成对应语言的类，用顺手的语言写抓包器 / MITM / 造包 bot。反推 `.proto` 的价值就是：**从游戏的 Lua 定义，拿到一把能在任何语言里收发这游戏协议的钥匙**。

## 三、检查点

- 能说清"protobuf wire 没字段名、名字在 Lua 侧定义里"，以及为什么因此能反推 `.proto`。
- 能从 `_pb.lua` 反推出可编译的 `.proto` + opcode 映射，并字段级验证（type/label 常量查表、tag 号要精确）。
- 认得几种真实形态（starwing `pb.load` 二进制描述符 / protoc-gen-lua 逐字段 / sproto），不把逐字段 `_pb.lua` 当唯一形态。
- 知道 `.proto` 可 `protoc` 生成任意语言的类，写自己的协议工具。
