## 一、本章的目的

5.1 说了：**V8 后端的 puerts 脚本层一定是明文 JS**，拆包即见。真实游戏当然不会裸奔——但因为 V8 上不了字节码，它**唯一能加的防守是源码级混淆**。这一课就看这层防守长什么样、怎么破：拿一个用 **`javascript-obfuscator`** 混淆过的真 puerts 游戏，抠出 JS、去混淆、读出逻辑。

> **为什么只能源码混淆**：JS 的反射（`Object.keys`/`for..in`/`fn.toString()`/按名取属性）依赖运行时明文，编成字节码这些元信息还得可得、抹不掉；V8 cachedData 又跨版本死锁、生产不可控。所以 V8 puerts 的安全上限就是**在源码这一层做混淆**，运行的还是（混淆后的）JS。

## 二、javascript-obfuscator 的几板斧 + 怎么破

`javascript-obfuscator`（业界最常见的 JS 混淆器）主要几招，各有对应的去混淆：

| 混淆手法 | 长什么样 | 去混淆 |
|---|---|---|
| **改名** | `a`/`_0x1a2b`/`a0_0x…` 顶替所有标识符 | 靠字符串 + 调用关系猜语义（同 il2cpp strip 后重命名） |
| **字符串数组 + 编码** | 所有字符串抽进一个数组、`base64`/`rc4` 编码，用 `_0x1234(idx)` 取 | **还原字符串数组**：解码数组、把索引访问替换回明文串——一步就把 flag/函数名捞回来 |
| **数组轮转（rotate）** | 启动时一个自执行函数把字符串数组旋转 N 位 | 跑一遍那个 rotate 函数、或让工具模拟 |
| **控制流平坦化** | 逻辑拆成 `while(true){switch(state){…}}` 状态机 | **反平坦化**：按 state 顺序把 case 拼回顺序结构 |
| **死代码注入** | 塞永不执行的假分支干扰阅读 | 常量折叠 / 去死支 |

**工具一把过**：[`webcrack`](https://github.com/j4k0xb/webcrack)（现代、强）或 `synchrony`——喂混淆 JS，自动还原字符串数组 + 反平坦化 + 去死代码，输出接近原始的可读 JS。手工也行：先解字符串数组（明文串就回来了，flag 往往就在里面），再按需反平坦化读控制流。

> **离线兜底（无需 `npx` 联网装 webcrack）**：混淆器自带的**解码器就在文件里**——那个 `_0x1234(idx)` 取值函数 + 启动时的数组轮转，本身就是一段能自解的 JS。直接用 `node` 执行这段混淆 JS，让它把字符串数组解开，再 `console.log` 出你要的那一项（如 flag 变量）即可。这正好印证本章那句：**混淆不改语义、信息都在文件里**——连它的解码逻辑也一并带着，跑一遍就自己吐出来。

> **关键认知**：混淆**不改变语义、不加密**——运行时 V8 吃的还是这段 JS，所有信息都在文件里，只是被打乱。所以**一定能静态还原**，只是费点力；这和"整体加密（找 key）"是两回事。

## 三、检查点

- 能说清 V8 puerts 为什么**只能源码级混淆**（反射依赖运行时明文 + 字节码不可控）。
- 认得 `javascript-obfuscator` 的几板斧（改名 / 字符串数组+编码 / 轮转 / 控制流平坦化 / 死代码）。
- 会用 `webcrack`（或手工解字符串数组 + 反平坦化）把混淆 JS 还原到可读，读出逻辑 / 捞出字符串。
- 知道混淆 ≠ 加密：语义没变、信息都在，一定能静态还原。

## 小结 & 下一部分
